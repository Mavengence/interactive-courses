The AI Tools
Ecosystem.

Claude Code, Copilot, Cursor, Aider, Cline — each solves a different slice of the problem. Picking the wrong one for a job is expensive. Picking the right one is a force multiplier.

⏳ 11 min read ◆ 3 interactives ✦ +50 XP available

The AI coding landscape fragmented fast. In 2023 there was essentially one tool. In 2025 there are five major categories, each with a different philosophy: inline completions, chat-driven editing, CLI agents, IDE-native agents, and autonomous PR generators. They are not interchangeable.

The mistake most developers make is treating their first tool as a permanent tool — defaulting to Copilot autocomplete for tasks that need a full agent, or spinning up an autonomous agent for a one-liner fix that would take seconds in an IDE. The cost is compounded daily.

This lesson is a map. Know the landscape, and you spend your time in flow rather than fighting your toolchain.

The five major tools

GitHub Copilot

The inline completer

Lives in your editor. Autocompletes at the cursor. Best for: boilerplate, repetitive patterns, filling out function bodies you already know the shape of. Worst for: architectural decisions, multi-file refactors, anything that requires reading context beyond the open file.

Cursor

The IDE-native agent

A VSCode fork with AI deeply woven in. Chat with the whole codebase as context. Agent mode can run terminal commands, edit multiple files, and iterate. Best for: interactive brownfield exploration, multi-file edits where you want to watch and steer in real time.

Claude Code

The terminal-first agent

Runs in your existing terminal. Full repo access, shell execution, no dedicated IDE. Best for: developers who live in the terminal and want a capable agent that doesn't change their editor. Integrates naturally with git, CI, and custom scripts via hooks.

Aider

The open-source CLI agent

Open-source, model-agnostic CLI. You pick the model (GPT-4, Claude, Gemini). Best for: teams that want to bring their own API keys, want full auditability, or need to run air-gapped. Strong git integration — it commits as it goes.

Cline (formerly Claude Dev)

The VSCode extension agent

VSCode extension that gives you an agentic AI inside your existing editor, not a fork. Supports multiple models. Best for: teams already on VSCode who want agent-level power without switching editors. MCP support makes it highly extensible.

Codex (OpenAI)

The cloud PR agent

The subject of this course. Runs in an isolated cloud sandbox. Async — you submit a task, come back to a PR. Best for: high-volume parallel work, tasks you can fully specify upfront, freeing your local machine for interactive work.

Choosing by task shape

The right tool depends on the task shape, not on loyalty to a vendor. A rough decision tree:

  • You know what you want and it's one file → Copilot autocomplete is fastest. Don't spawn an agent.
  • You want to explore a codebase you don't know → Cursor or Cline. Chat with context, ask questions, steer in real time.
  • You have a well-specified task and want your hands free → Codex (cloud) or Aider (local). Write the spec, let it run, review the PR.
  • You live in the terminal and want a capable REPL-style agent → Claude Code. Fast, composable, hooks into your existing workflow.
  • You need model flexibility or air-gapped operation → Aider. Bring your own model.

MCP servers: extending the agents

MCP stands for Model Context Protocol — a standard for connecting AI agents to external tools, data sources, and services. Think of it as a plugin system for your agent.

Without MCP, an agent can only see your local filesystem and run shell commands. With MCP, it can query a database, search the web, create GitHub issues, read Slack threads, or call any API — all through a standard interface the agent already knows how to use.

The architecture is simple:

# How MCP works (conceptually)

# 1. You configure MCP servers in your agent's config
#    (e.g. ~/.claude/settings.json for Claude Code)

# 2. Each server exposes "tools" — named functions the agent can call
#    e.g. mcp__github__create_issue({ title, body, labels })
#         mcp__postgres__query({ sql })
#         mcp__slack__send_message({ channel, text })

# 3. The agent decides when to call them, just like any other tool
#    You don't have to orchestrate the calls manually

# Example: Claude Code with GitHub and Postgres MCP servers
# Agent can now: read the DB schema, open a GitHub issue,
# and commit a migration — all in one session

Supported by: Claude Code, Cline, Cursor (via extensions), and a growing list of other agents. MCP servers exist for GitHub, GitLab, Postgres, Supabase, Stripe, Slack, Google Drive, Jira, Linear, and dozens more. You can also write custom MCP servers for your internal tools.

The practical upside: your agent can participate in your full toolchain, not just your local filesystem. A task that previously required manual steps ("run the query, paste the result into the prompt") becomes a single agent-handled loop.

IDE integration patterns

Even non-IDE tools (Codex, Aider, Claude Code) integrate with your editor workflow. The common patterns:

  • Diff review in your editor: Codex and Aider both produce git diffs. Open the PR in your editor's git UI to review — same flow as any human PR.
  • Running agents on save: Some teams configure Claude Code or Aider to run a quick check (lint, type check, failing tests only) on every file save. Tight feedback loop without context-switching.
  • Editor context for the CLI: Claude Code can read your currently-open files from many editors via filesystem watching. You don't have to paste files — just reference them by name.
  • Parallel sessions: Use git worktrees (next lesson) to run an agent on a feature branch while you keep working in main. No context conflicts between the sessions.
